# 语言模型指纹保持实验总体路线

## 研究要解决的问题

本研究关注一个实际问题：语言模型被植入主动指令指纹后，在经历继续微调、量化或提示包装等部署变换时，指纹是否仍然能够被黑盒查询稳定验证。研究不仅要证明模型能够记住指纹，还要区分正常模型与带指纹模型、衡量部署后的遗忘程度，并判断有针对性的指纹设计能否提高保持率而不过度影响模型能力。

## 为什么先做P0–P2

P0–P2是工程验证，不是论文主实验。它们依次回答三个基础问题：云端GPU和软件环境是否可靠；原始模型是否会偶然回答演示代号；LoRA训练、保存、重载、合并和再次验证的整条工程链路是否可用。

这三步的作用是排除环境、缓存、解码方式和模型保存流程造成的错误。P2使用的8条公开演示指纹只用于证明闭环能跑通，不能与后续32条指纹或正式实验结果混合统计，也不能作为方法有效性的主要证据。

## 方法预实验P3–P6

### P3：候选指纹构建与负例筛查

构建32条候选指纹，先在未注入指纹的原始模型上检查自然命中和误报。只有负例表现合格的指纹才能进入后续预实验。

### P4：普通均匀LoRA基线

使用相同权重训练全部32条指纹，建立最简单、可重复的注入基线。该阶段提供后续方法比较所需的参考点，但仍属于参数和流程探索。

### P5：模拟部署后的继续微调

在基线模型上实施受控的继续微调，观察指纹随部署训练强度增加而遗忘的速度，同时监测模型原有能力是否明显下降。

### P6：易遗忘识别与加权方法

利用前一阶段的遗忘信号识别脆弱指纹，并比较加权注入方法与普通均匀基线。P6用于判断研究创新是否值得进入更大规模验证，并帮助冻结正式实验参数。

## 进入正式实验的条件

只有在P3–P6全部完成、数据与指标可以复现、候选方法优于合理基线且没有明显能力损伤后，才能进入F0。F0需要一次性冻结正式指纹数据、模型选择、随机种子、训练配置、部署变换、评价指标和统计方案。冻结后不得根据正式结果反向调整方法；确需调整时，应重新建立正式实验版本并说明原因。

## 正式实验F0–F4

- F0负责冻结实验协议和版本。
- F1在两个基础模型、候选方法和三个随机种子上完成主要对比。
- F2评估继续微调强度、量化和提示包装等部署鲁棒性。
- F3检查独立原始模型误报、能力保持和其他安全边界。
- F4完成消融、统计检验以及论文图表生成。

具体模型、方法数量和参数现在只是占位，须等方法预实验完成后确定。

## 哪些结果可以进入论文

F系列冻结后产生的数据才能进入论文主表、主图、主要统计检验和主要结论。P3–P6可用于说明方法形成过程、参数选择依据或补充实验，但不能冒充预注册的多模型、多随机种子正式结果。P0–P2只能用于环境说明、实现验证或附录中的工程复现信息。

## 每个阶段完成后的管理方式

每个阶段通过后都应保留原始运行目录，复制小型报告到对应层级，计算归档文件SHA256，并更新 `docs/experiment_registry.md`。如果阶段失败，也应保留原始运行并记录失败原因，但不得把失败运行登记为当前有效结果。新运行还应记录父运行、Git提交和实验层级，使任何表格数据都能追溯到准确代码和原始文件。
