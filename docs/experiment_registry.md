## 后续更新规则

每完成一个新阶段，应按以下顺序更新：

1. 保留唯一的原始 `runs/` 目录，不移动、重命名或覆盖。
2. 根据阶段验收字段判断是否通过，不能只凭终端输出或主观判断。
3. 将小型结果复制到对应的 `reports/pilot/` 或 `reports/formal/` 目录，不归档模型权重。
4. 为报告生成 `archive_manifest.json`，记录实际文件大小和 SHA256。
5. 更新本总账的状态、有效 run ID、真实指标和相对报告路径。
6. 在新运行的 `resolved_config.json` 中记录 `stage_id`、`experiment_tier`、`paper_usage`、`parent_run_ids` 和 `git_commit`。
